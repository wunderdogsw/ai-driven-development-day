# Add an EF Core migration

Change the model, let EF Core generate the migration, check it for data loss, and test it. You never write or edit a migration file by hand. A hook blocks edits in `Migrations/`.

## Before you start

- Write down in one line what changes: entity, property, type, required or optional.
- **Stop and ask** if the change removes or renames a column or table. A human decides about data loss. Before you ask, count the rows that have data in that column with the `devdb` MCP server (read-only, dev database), so the question shows what would be lost.
- Not for data fixes (changing rows). Those need a script and a human review. Say so and stop.

## Steps

1. **Change the model.** Edit the entity in `src/Domain/Entities/` and its configuration in `src/Infrastructure/Persistence/Configurations/<Entity>Configuration.cs`. Set length, required and indexes in the configuration, not with attributes.
2. **Name the migration.** PascalCase, verb + what + where: `AddPhoneToUsers`, `CreateOrderNotesTable`, `AddIndexOnOrdersCreatedAt`.
3. **Generate it.**
   ```bash
   dotnet ef migrations add <Name> --project src/Infrastructure --startup-project src/Api
   ```
4. **Check it.**
   ```bash
   ${CLAUDE_SKILL_DIR}/scripts/check-migration.sh <Name>
   ```
   It fails on dropped or renamed columns and tables, and on a column that becomes required without a default. If it fails, stop and show the user the lines it printed.
5. **Read the SQL.**
   ```bash
   dotnet ef migrations script <PreviousName> <Name> --project src/Infrastructure --startup-project src/Api
   ```
   The SQL must do only what the request asked. Anything else: stop and ask.
6. **Compare with the real schema.** Use the `devdb` MCP server to read the table as it is in the dev database. If it differs from the model snapshot (a column someone added by hand), stop and ask.
7. **Test it.**
   ```bash
   dotnet test tests/Infrastructure.Tests --filter Category=Migrations
   ```
   These tests apply every migration to an empty database, then roll the newest one back.
8. **Report** in the format below.

## If something goes wrong

- **Wrong migration generated** → `dotnet ef migrations remove --project src/Infrastructure --startup-project src/Api`, fix the model, generate again. Never edit the file.
- **`AppDbContextModelSnapshot.cs` changed** → expected. It is generated with every migration.
- **`dotnet ef` fails to build** → fix the model code first. The tool needs a project that builds.
- **`devdb` MCP server not connected** → skip the data count and the schema check, and say so in the report. Don't connect to a database any other way.

## Report

```
Migration: AddPhoneToUsers
Model: User.Phone (nvarchar(20), optional)
Check: passed, no data loss
Schema: matches dev database (devdb)
SQL: ALTER TABLE [Users] ADD [Phone] nvarchar(20) NULL;
Tests: dotnet test --filter Category=Migrations → Passed 12, Failed 0
```

# Examples

## 1. Goes through

**Request:** "We need to store a phone number for users. Max 20 characters, optional."

**What you do:**

1. One line: `User.Phone, string, max 20, optional`.
2. Add `public string? Phone { get; set; }` to `src/Domain/Entities/User.cs`.
3. In `UserConfiguration.cs`: `builder.Property(u => u.Phone).HasMaxLength(20);`
4. `dotnet ef migrations add AddPhoneToUsers --project src/Infrastructure --startup-project src/Api`
5. Check script: passed.
6. `devdb`: `Users` in the dev database matches the model snapshot.
7. SQL: `ALTER TABLE [Users] ADD [Phone] nvarchar(20) NULL;` Only what was asked.
8. Tests: passed.

**Report:**

```
Migration: AddPhoneToUsers
Model: User.Phone (nvarchar(20), optional)
Check: passed, no data loss
Schema: matches dev database (devdb)
SQL: ALTER TABLE [Users] ADD [Phone] nvarchar(20) NULL;
Tests: dotnet test --filter Category=Migrations → Passed 12, Failed 0
```

## 2. Stops for a question

**Request:** "Remove the Fax column from Customers, nobody uses it."

**What you do:** Don't generate anything yet. Removing a column deletes data. Count it first with the `devdb` MCP server:

```sql
SELECT COUNT(*) AS total, COUNT(Fax) AS with_fax FROM Customers;
```

Result: 52,310 customers, 1,204 with a fax number. Then ask:

> Removing `Customer.Fax` deletes the fax number of 1,204 customers (dev database). `git log -S Fax` shows the code last wrote it in 2023. How do you want to do it?
> a) Remove it now (data is lost)
> b) Stop using it in code first, remove the column in a later release
> c) Keep it

Go on only after the user answers. Write the answer in the report as `Decision: <answer> (<name>)`.

## 3. Not a migration

**Request:** "Set all customers without a country to Finland."

**What you do:** Stop. This changes rows, not the model. Say:

> This is a data fix, not a migration. It needs a SQL script that a human reviews and runs. I won't add a migration for it.

Finds data loss in the new migration: dropped or renamed columns and tables, and columns that become required without a default. Exit code 1 stops the skill. Tested on a sample migration.

.claude/skills/add-ef-migration/scripts/check-migration.sh
#!/usr/bin/env bash
# Fails when a migration can lose data.
# Usage: check-migration.sh <MigrationName>
set -euo pipefail

name="${1:?Usage: check-migration.sh <MigrationName>}"
file=$(ls src/Infrastructure/Migrations/*_"$name".cs 2>/dev/null | grep -v '\.Designer\.cs$' | head -1 || true)
[ -n "$file" ] || { echo "✗ No migration file found for $name"; exit 1; }

# Only the Up() method matters: that is what runs on deploy.
up=$(awk '/void Up\(/{on=1} /void Down\(/{on=0} on{print FNR": "$0}' "$file")
up_raw=$(awk '/void Up\(/{on=1} /void Down\(/{on=0} on' "$file")

fail=0
risky=$(echo "$up" | grep -E 'migrationBuilder\.(DropColumn|DropTable|RenameColumn|RenameTable)' || true)
if [ -n "$risky" ]; then
  echo "✗ Drops or renames a column or table:"
  echo "$risky"
  fail=1
fi

# A column that becomes required without a default fails on existing NULL rows.
required=$(echo "$up_raw" | tr -s '\n ' ' ' | grep -Eo 'AlterColumn<[^;]*;' \
  | grep 'nullable: false' | grep 'oldNullable: true' | grep -v 'defaultValue' || true)
if [ -n "$required" ]; then
  echo "✗ Makes a column required without a default value:"
  echo "$required"
  fail=1
fi

[ "$fail" -eq 0 ] && echo "✓ $name: no data loss found"
exit "$fail"
