Example skills

The skills and subagents the hands-on guide uses as its model. Read why each one is built the way it is, then copy the files into your repo's .claude/ folder and change the paths and commands.

  • Example skill · general/add-ef-migration

    A skill for one task the team repeats: adding a database migration in the .NET API. It shows what makes a skill reliable: exact commands, stop rules, a script for the mechanical check, worked examples and evals.

  • Example skill · Part 4/discover

    Turns a ticket into precise acceptance criteria and a sequence diagram. It only reads: it collects evidence, lists what is unclear, asks the human one question at a time, and writes plans/<ticket>/acs.md and sequence.md.

  • Example skill · Part 4/plan

    Turns approved acceptance criteria into a build plan: every step serves an AC, every file is named, every AC has a test with the exact command that runs it. Runs in plan mode and ends by showing the ACs, the diagram and the plan together, with one question: Do you approve?

  • Example skill · Parts 4–5/implement

    Builds a ticket from its approved plan in a fresh session: tests first, then code. Two hooks come with the skill: a lock that keeps the approved tests and plan unchanged, and a gate that only lets Claude finish when every AC test and check passes.

  • Example skill · Part 5/review

    The review skill leads a team of independent subagents: two verify facts, two or three review the code and the logic. It cross-checks what they found, keeps what holds up, and writes review comments, on the PR or in a local file before there is a PR. It never edits code.
